# YatraLens implementation status

This file reports implemented behavior, not PRD acceptance. The product brief is `YATRALENS_MASTER_PRD.md`. The build is a local development prototype.

## Voice-first assistant status (2026-11-22)

- The Android build can be selected as the phone's default assistant. On the iQOO Android 16 test phone, `KEYCODE_ASSIST` summoned an animated green system-hosted YatraLens bubble over the launcher and over another app while the YatraLens activity was closed. The test temporarily selected YatraLens, then restored Google as the default assistant; both role and secure service setting were verified restored.
- The bubble asks what help is needed and accepts one short on-device recognition turn where Android provides that engine, or typed text. With per-request cloud consent, Sarvam 105B returns a constrained feature plan. A live bubble test for “Read the bus board” asked where the traveller was going; a second request returned the bus-board action. Continuing opened the matching YatraLens assistant task after an initial Android voice-activity compatibility error was fixed and retested.
- The app's BioGym-inspired forest, sage, sand and ivory theme is installed. A cross-trip, time-sorted contextual-memory timeline and a three-item home preview are built; one physical-phone database test for cross-trip timeline aggregation passed. The timeline screen itself has not had a manual phone review after this change.
- An opt-in local Vosk detector for “Hello assistant” has since been added to the selected Android voice service. It uses a bundled, hash-pinned English model, keeps wake audio on-device, shows an ongoing notification, pauses during an assistant session or trip, and stops when YatraLens is no longer the selected assistant or Android reports severe heat. Two physical-phone tests passed: model loading and offline recognition of a synthetic “Hello assistant” WAV. A real live-microphone, closed-app utterance, false-trigger rate and battery/thermal endurance remain unverified.
- **New UI acceptance status:** The launcher is now a compact trip brief and timestamped, source-labeled contextual-memory timeline. The system assistant bubble routes F01–F13 actions with in-bubble sensor consent, controls, results, translation review and speech. Scene, weather, transport, culture, discovery and destination results become dated context notes; raw OCR and spoken turns still require review before evidence is saved. The legacy feature screen remains in the code but is no longer the launcher or notification destination. The compact bubble opened over the launcher on the physical phone while the app was closed. Local “offline help” and “memory” requests displayed their results inside it without cloud consent. A Sarvam-planned Talk & Listen request opened its controls, and after separate sensor opt-in the bubble started a microphone/location foreground trip with the camera off. That trip was ended without sending audio to Sarvam. A location-only weather check returned a live sourced forecast after the GPS readiness fix. The bubble Read Anything crop reached Sarvam OCR and returned text and translation; accuracy against a controlled sign is still untested. Other bubble tasks still await phone acceptance. The command is “Hello assistant”; live closed-app spoken wake and the brand phrase remain unverified. Google was restored as the phone's default assistant after testing.

## Run locally

1. Put `SARVAM_API_KEY` and `YATRALENS_DEV_TOKEN` in the ignored `.env` using `.env.example` as a template.
2. Install `backend/requirements.txt` and run `uvicorn backend.app.main:app --host 127.0.0.1 --port 8000` from the repository root.
3. Run `adb reverse tcp:8000 tcp:8000` with the unlocked phone attached.
4. Build from `android/` with `.\gradlew.bat :app:assembleDebug`; install `android/app/build/outputs/apk/debug/app-debug.apk`.

The debug APK contains only a disposable development token. It contacts `127.0.0.1` through ADB reverse; it is not a deployable production client.
